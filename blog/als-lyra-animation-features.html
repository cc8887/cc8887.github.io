ALS V4 与 Lyra：五种动画机制逐项拆解

锁脚、原地转向、攀爬、交叉步和换道具，都不能仅靠“播一段动画”解决。五个同步三维场景把输入、门控、姿态和最终结果分开，并指出哪些内容有原图依据，哪些只是教学参照。

01 / 锁脚：谁拥有地面上的接触点？

支撑脚落地后，角色胶囊仍可能前进或旋转。若脚只跟随骨架局部坐标，地面上的鞋会被根节点拖走。一个有效的锁脚系统至少需要接触权重、稳定的脚点、每帧的根运动补偿，以及进入和退出支撑期的规则。

脚点世界位置 = 接触锚点；脚点局部位置 = 接触锚点 − 当前根位置
ALS V4 原图FootLock_L/R 曲线给左右脚锁定权重，脚部控制按当前根和地面信息补偿。它不同于停步时决定左右脚分支的 Feet_Position。
右侧参照故意保留未约束的输入脚点，显示滑脚如何产生。它不是 Lyra 的最终脚部输出；Epic 公开的动画概览没有给出可逐节点复核的脚锁捕获、释放规则。

移动平台再增加一个坐标系：脚点要随平台走，同时不能随角色在平台上的移动而漂移。演示的“移动平台”模式使用本地 Refactored 的基座局部锚点扩展；不能把这个扩展写成原 ALS V4 的逐帧实现。把锁定权重调低，可以看到从原始脚位到锚点的混合。

依据：本地脚锁版本边界、最终接触锚点验证、Epic Lyra 动画概览。

02 / 原地转向：让身体追上目标朝向

若控制器一转、Actor 就直接跟转，尚未抬起的脚会绕角色中心扫过地面。若模型完全不转，枪口与身体方向又会持续分离。ALS 与 Lyra 都有转身动画，但暂存朝向差的位置不同。

ALS V4：选片并驱动 Actor按目标角符号选左/右；绝对角度严格小于 130° 选 90° 资产，否则选 180°。站/蹲有各自的转身资源，Turn/Rotate Slot 在 Not Moving 内混入，动画曲线和倍率参与实际旋转。
Lyra：Root Yaw Offset 暂存差值Actor 跟随 Controller 先转，Rotate Root Bone 以反向 Root Yaw Offset 暂时保持模型朝向；Idle 转身片段的曲线逐步释放偏移。模式包含 Accumulate、Hold、Blend Out。

交互页可以把目标角拖过 130°：左侧切换资产档位；右侧读数显示 Offset 如何从负的目标角回到 0。右侧的武器子 AnimBP 还能改变转身片段和延迟。三维人物的脚步轨迹是用于读懂变量的示意，不是原始动画资源的逐帧重放。

依据：ALS 选片规则、Turn Slot 接线、Epic Lyra 转身说明。

03 / 攀爬：先判定空间，再播放动作

按下攀爬键不意味着必然起播。角色要找到前方墙面、可站的顶部和穿越过程的净空；还要按台高、空中状态与手中道具选动作，并把最终落点对齐到真实平台。移动平台的目标位置在动作期间也会变化。

本地 ALS Mantle 链前向/顶部/净空探测 → 高度与 Overlay 选 Montage → RootMotionSource 对齐根轨迹 → 平台局部目标。地面高度范围为 50–225 cm，空中为 50–150 cm；无净空时拒绝起播。
Lyra 公开资料的范围官方动画概览可核对 Jump、Fall、Land/Idle 等基础空中路径，却未提供可验证的 Mantle 查询、选片与根运动图。右侧只用这条跳跃路径作参照，不能据此推断 Lyra 是否具备其他攀爬实现。

演示中把净空切为“阻挡”，左侧会保持在台下且不触发动作；调整高度可观察可接受台面与根轨迹。三维障碍、射线和轨迹用于解释门控，不包含完整 CharacterMovement 碰撞求解。

依据：普通 Demo 的 Mantle 接入、Mantle 输入与资源、Epic Lyra 空中状态说明。

04 / 交叉步：输入反向不等于马上换髋

右横移途中突然要求向左，当前一只脚可能正跨过身体中线。当帧直接换成相反的腿部姿态，会让双腿交错或瞬间换位。动画系统需要知道当前是否正在交叉，同时保留新的移动意图。

ALS V4：等动画窗口六方向 F/B/LF/LB/RF/RB 与 VelocityBlend 提供移动姿态。中性换髋需 Feet_Crossing = 0、源状态权重为 1、|HipOrientation_Bias| < 0.5，之后经 ChangeDirection 曲线和腿部 BlendProfile 过渡。
Lyra：适配方向覆盖官方文档描述四向 Strafe 资产与起步时的 Orientation Warping。它解释了请求角度与下身方向如何适配；公开说明没有提供与 Feet_Crossing 对应的交叉步换髋门控。

交互页把摆动脚跨线和抬脚刻意放大。时间轴停在“脚交叉/等待”时，左侧保持原髋；解除交叉且偏向条件满足后才换向。Feet_Crossing 是换髋窗口信号，绝不是上一篇停步使用的 Feet_Position 左右脚曲线。

依据：ALS 方向图审计、换髋门控验证、Epic Orientation Warping 说明。

05 / 换道具：网格、挂点和动画层必须一致

换成手枪时，改的不是一张手枪模型而已。双手如何握持、上身如何瞄准、移动和原地转向用哪组资源，以及道具挂在哪根骨上，都要与装备状态同步。只切一边会出现空手握枪或手穿过道具。

ALS V4：Overlay 驱动姿态本地导出有 13 种 Overlay。Rifle、Pistol、Bow、Torch、Box 等分支选择姿态/上身动画，道具附着于对应虚拟手骨并随最终骨骼更新；弓拉弦还有曲线驱动的姿态。
Lyra：装备链接子动画层Quick Bar 选择装备，EquipmentDefinition/Instance 生成持物 Actor。武器子 AnimBP 可继承 ABP_ItemAnimLayersBase，通过 Link Anim Class Layers 替换移动、瞄准和骨骼控制等实现。

在演示中切换手枪与步枪，可以看到左侧 Overlay、右侧武器层和手中物体一同变化。弓、火把、箱子在右侧标为需自行扩展，没有把 ALS 的这些资产误认成 Lyra 自带示例。切换时间只表达依赖顺序，不模拟网络装备事务。

依据：ALS Overlay 与道具挂点、Epic Lyra 装备系统、Epic Lyra 动画层。

怎样读这组对照

左侧围绕本地 ALS V4 原图和移植验证记录构造机制模型。脚锁移动平台和 Mantle 生产接入包含本地 Refactored/Godot 扩展，文章已分别标注。右侧只有原地转向、方向适配和装备层可直接对照 Lyra 官方说明；锁脚与攀爬使用明确标识的参照场景。程序化三维人物用于读懂状态、阈值和结果，不能作为原始 UE 资产逐帧运动精度的证据。
