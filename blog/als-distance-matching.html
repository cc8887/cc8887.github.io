ALS 停步与 Distance Matching：脚步相位和距离曲线

松开移动输入后，角色仍在减速，循环动画也可能刚好走到半步。停在哪里、选哪只脚承重、怎样让脚不被角色根部拖走，是三个不同的问题。先看冲突，再看 ALS 和 Distance Matching 各自解决了哪一部分。

2026.09.28ALS / Unreal Engine约 9 分钟

停步为什么比“把速度降到零”难？

玩家松开输入只表示“不再要求继续移动”。物理胶囊仍有速度，会按制动参数继续前进；动画循环此时可能是左脚着地，也可能是右脚着地或双脚交接。如果直接切到同一帧站立姿势，脚会突然换位；如果让循环照常播放到物理停住，脚又可能在地面上被拖着滑行。

因此停步至少需要两个决定：从当前哪一步接入，以及怎样让动画位移追上物理停点。ALS 主要用状态和脚步曲线处理前者；Distance Matching 让剩余距离参与动画时间选择，主要处理后者。两者都还需要脚接触处理。

先固定角色的运动

对照实验使用初速度 5 m/s、制动减速度 4 m/s² 的简化模型。角色在 1.25 秒后停下，共移动 3.125 m；两侧始终共享这条轨迹。这样看到的差别来自动画时间和落脚策略，不是角色移动速度不同。

tstop = v0 / a = 1.25 s 　·　 dstop = v0² / (2a) = 3.125 m

公式只属于这段匀减速教学模型，不计摩擦。Unreal 中可以用 Predict Ground Movement Stop Location 按 Character Movement 的速度、地面摩擦和制动参数预测停止偏移；该偏移的长度才是当前预测的剩余距离。

ALS：先读脚步曲线，再选停步分支

这里以项目中的原 ALS V4 Stop 图为准。移动动画携带 Feet_Position 曲线：负值指向左脚，正值指向右脚；绝对值越接近 1，越接近明确的单脚落地相位，接近 0 则处在双脚交接附近。它是步态信号，不是角色到停点的米数，也不是 FootLock_L/R 锁脚曲线。

p ≤ −0.5Lock Left左脚已进入明确落地相位，保留左脚支撑。
−0.5 < p < 0Plant Left左脚侧但尚未压实，过渡到左脚落地姿势。
0 < p < 0.5Plant Right右脚侧但尚未压实，过渡到右脚落地姿势。
p ≥ 0.5Lock Right右脚已进入明确落地相位，保留右脚支撑。

实际流程是：移动状态失去继续移动条件后进入 Stop；Stop 从上一轮已求值的移动姿态读取曲线值 p；先按 |p| ≥ 0.5 分到 Foot Down / Lock，否则进入 Foot Up / Plant，再按正负选择左或右。恰好 p = 0 时，原 V4 图没有合法的左右终端边，会暂留在 Pre-Stop，而不是随意指定一只脚。

Lock 沿用当前移动姿态，并把选中侧的 FootLock_L 或 FootLock_R 写为 1；Plant 则从六个移动方向的固定帧姿态中混合出目标落脚姿势，覆盖对应腿部，再写同侧脚锁曲线。进入左右 Stop 状态还会触发相应的过渡动作。选脚的是 Feet_Position，维持接触的是脚锁与后续脚部处理，两者职责不同。

版本边界：项目中的 Refactored Stop 读取 Parent.FeetState.FootPlantedAmount，依次检查 > 0.5 右 Lock、≤ −0.5 左 Lock、> 0 右 Plant、≤ 0 左 Plant。因此 +0.5 与 0 的边界行为不同，不能把两版规则合并成同一张表。视频左侧也只模拟“选一只支撑脚并固定世界脚点”，没有执行这些原生图节点。

这些分支帮助循环步态自然接入停步，但没有预测角色将在多远处停住。如果物理制动距离与停步片段的位移不合，仍要另行处理动画时间或位移误差。

Distance Matching：剩余距离决定片段时间

先用当前速度和制动参数预测到停点还剩多少距离。停步片段预先烘焙一条距离曲线 C(t)：每个动画时刻记录“片段根部相对最终停点还有多远”，终点之前为负，最后一帧为 0。运行时用目标值 −d 反查片段时间；同一剩余距离对应同一动画位移阶段。

d = v² / (2a) → C(t) = −d → tanim = C−1(−d)

沿用上图的制动过程：到 t = 0.625 s 时，角色速度是 2.5 m/s，预测剩余 d = 2.5² / (2 × 4) = 0.78125 m。在演示的 3.2 m / 1.08 s 停步片段中查 C(t) = −0.78125 m，得到 t_anim ≈ 0.547 s。物理时间走到 0.625 秒，并不要求动画也播放到 0.625 秒。

这个演示要求曲线在停步区间内单调，因而可以二分定位并在相邻采样之间插值。每帧查出的 t_anim 同时决定片段根位移和骨骼姿态。所需距离超出片段覆盖范围时，演示先保留移动循环，进入范围后再匹配。

对应到 Unreal 动画图

  1. 预测停点从移动组件预测当前到最终停点的偏移，而不是假设所有角色都按 v² / 2a 制动。
  2. 准备片段从停步动画的根位移生成 XY 距离曲线，使“每一帧距终点还有多远”可被查询；按官方示例配置可运行时索引的曲线压缩。
  3. 逐帧取姿态在 Sequence Evaluator 的 On Update 中，把剩余距离与曲线名交给 Distance Match to Target；它设置显式时间，由 Evaluator 产出姿态。
  4. 处理接缝检查入口脚步相位、预测偏差和脚部接触。距离相等只说明选中了相应的位移阶段，不保证上一段跑步循环与新姿态连续。

Epic 的节点文档明确指出，按剩余距离直接设动画时间不会保留上一段动画的脚步相位。Lyra 的官方说明还介绍了距离匹配与 Stride Warping 的配合；因此本文的显式反查图只解释一种核心机制，不把 Lyra 各状态的完整动画图简化成单个节点。

参照：Unreal Distance Matching 工作流、Distance Match to Target 节点、停点预测节点、Lyra 动画说明。

为什么反查时间后仍可能滑步？

距离匹配只回答“取哪一帧”，并不自动保证该帧的支撑脚固定。此前演示直接按归一化进度移动脚的位置，角色根部前进时脚也随之平移，所以出现滑步。

现在片段为每一步记录接触窗口和接触点。支撑期的局部脚位置由世界接触点减去当前根位置得到，因此角色向前走时脚保持在地面同一点；摆动期才让脚抬起并移向下一个接触点。

xfoot, local = xcontact, world − xroot, world

真实动画资产还需要处理片段入口相位、预测误差、地形高度、骨骼插值和 IK。这段视频验证的是距离曲线反查与程序化接触轨迹的机制，不是 Lyra 原始骨骼动画的逐帧复现，也不是 ALS V4 原图的逐帧复现。

决定动画时间播放器与状态过渡继续推进每帧按剩余距离反查 C(t)

两种方法可以组合：距离匹配负责时间与目标位置，状态机和脚部处理负责相位连续与落地稳定。
